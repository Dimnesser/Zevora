# ZEVORA

Игровая платформа в стиле кейс-сайтов CS2: открытие кейсов, апгрейд
предметов, инвентарь, вывод скинов и закрытая партнёрская программа.

Полностью рабочий фронтенд — все кнопки выполняют реальные действия над
состоянием приложения. Баланс, инвентарь и статистика живут в persist-сторе,
поэтому сценарии воспроизводятся между перезагрузками.

---

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

```bash
npm run build && npm start   # продакшен-сборка
npm run typecheck            # tsc --noEmit
```

Демо-аккаунт создаётся автоматически: ник `dimnesser`, баланс 15 000 ₽, роль
`owner` (поэтому доступен раздел `/admin`). Сбросить состояние можно в меню
профиля или во вкладке «Настройки» админ-панели.

## Как устроена графика

Ни одного изображения: каждый скин рисуется как SVG.

1. `components/art/weaponPaths.ts` — силуэты одиннадцати классов оружия CS2
   (AK, M4, AWP, SMG, дробовики, пистолеты, три типа ножей, перчатки).
2. `components/art/SkinArt.tsx` — покрасочный слой. Палитра и узор
   (`hydro`, `fade`, `doppler`, `marble`, `circuit`, `camo`, `carbon`,
   `splatter`, `stripe`, `solid`) берутся из записи скина и превращаются в
   градиенты и SVG-паттерны.
3. `CaseArt.tsx` рисует изометрический ящик с эмблемой, `Avatar.tsx` —
   детерминированный идентикон по хешу ника.

Новый скин — это одна запись в `data/skins.ts`: рисовать ничего не нужно.

## Игровая математика

Вся математика вынесена в `lib/` и опубликована на странице `/fair`.

**Кейсы.** Дроп-таблица задаётся весами; вероятность предмета равна его весу,
делённому на сумму весов. Те же числа показываются на странице кейса до
открытия (`lib/roll.ts`).

**Износ.** Float смещён к средним значениям; категория износа даёт множитель
цены от ×0.72 (Battle-Scarred) до ×1.18 (Factory New). Метка Counter выпадает
в 10% случаев и добавляет 25% к цене.

**Апгрейд.** `chance = (ставка / цель) × 0.92`, ограничено диапазоном
1–85% (`lib/upgrade.ts`). Стрелка физически попадает в выигрышную дугу —
дуга и есть вероятность.

## Партнёрская программа

Ключевое правило: **статус выдаётся только владельцем вручную**. Его нельзя
купить, получить при регистрации или заработать автоматически.

- `/partners` для обычного пользователя — закрытый лендинг: привилегии,
  четыре уровня, критерии отбора, FAQ.
- `/partners` для партнёра — **Partner Lounge** со вступительной анимацией,
  персональной ссылкой и промокодом, шестью метриками, графиком за 14 дней,
  партнёрскими кейсами и списком выданных привилегий.
- Уровни: `Partner → Creator → Elite Partner → Zevora Ambassador`.
  Автоматического повышения нет.
- `/admin → Partners` — поиск пользователя, выдача и смена уровня, снятие
  статуса с подтверждением, редактирование привилегий, персональный
  промокод, партнёрская ссылка, размер daily и множителя рефералов,
  добавление в закрытые акции.

Партнёрские кейсы (`Zevora Vault`, `Lounge Reliquary`) скрыты из общего
каталога и появляются в нём сразу после выдачи статуса.

## Подключение бэкенда

Экраны не обращаются к данным напрямую — только через `services/api.ts`.
Чтобы перейти на реальный API, достаточно заменить тела методов:

```ts
// сейчас
async listCases(params) { return delay(visibleCases(params.partner)) }

// потом
async listCases(params) {
  return fetch(`${API_URL}/cases?${qs(params)}`).then(r => r.json())
}
```

`subscribeLiveDrops()` уже имеет форму подписки — сегодня это интервал,
завтра `new WebSocket(...)`, интерфейс ленты дропов не меняется.

Розыгрыш вынесен в чистые функции (`rollCase`, `rollUpgrade`), поэтому
перенос его на сервер не затрагивает анимации: рулетка и циферблат получают
уже определённый результат и лишь доигрывают его.

Доменная модель в `types/` спроектирована под реляционную схему: `User`,
`InventoryItem`, `Transaction`, `PartnerProfile` ложатся в таблицы без
переработки.

## Адаптивность и доступность

Проверено без горизонтального скролла на ширинах 320, 360, 390, 430, 768,
1024, 1280, 1440 и 1920 px.

Мобильная версия — не уменьшенный десктоп: отдельная нижняя навигация с
выделенной центральной кнопкой, модальные окна как bottom sheet, отдельные
плотности сеток и компактный хедер.

Учитывается `prefers-reduced-motion`; интерактивные элементы имеют
видимый focus-ring, иконки-кнопки — `aria-label`, вкладки — роли `tablist`.
