# ZEVORA

Игровая платформа в стиле кейс-сайтов CS2: открытие кейсов, апгрейд
предметов, инвентарь, вывод скинов и закрытая партнёрская программа.

Розыгрыш, баланс и инвентарь живут **на сервере**. Клиент показывает
анимацию уже известного результата и не может на него повлиять.

---

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

База создаётся и заполняется автоматически при первом запросе — никакого
отдельного шага миграции нет.

```bash
npm run build && npm start   # продакшен
npm run typecheck            # tsc --noEmit
npm run db:reset             # удалить базу и пересоздать с нуля
npm run import:skins         # импорт реальных изображений скинов
npm run verify:images        # проверка 20 эталонных URL
npm run verify:browser       # проверка тех же 20 в браузере
```

**Демо-аккаунты** (создаются сидом):

| Ник | Пароль | Роль |
|---|---|---|
| `dimnesser` | `zevora123` | владелец — доступ в `/admin` |
| `player` | `player123` | обычный игрок |

Кнопки быстрого входа есть на `/login`.

## База данных

| Таблица | Назначение |
|---|---|
| `users` | аккаунт, баланс (integer), роль, партнёрский статус |
| `sessions` | SHA-256 токена сессии, срок действия |
| `rarities` | редкости: цвет, эффект, вес по умолчанию, порядок |
| `skins` | каталог: `market_hash_name`, `image_url`, `image_source`, `image_status`, редкость, базовая цена |
| `skin_images` | журнал импорта: URL, HTTP-статус, content-type, размер, ширина/высота |
| `cases` | кейс: slug, цена, активность, партнёрский доступ |
| `case_items` | связка кейс↔скин: **вес**, диапазон float, StatTrak |
| `inventory_items` | экземпляры предметов игрока: износ, float, статус |
| `case_openings` | каждое открытие + **выигрышный билет и общий вес** |
| `transactions` | двойная запись: сумма и баланс после операции |
| `idempotency_keys` | защита от повторного выполнения, PK `(user_id, key)` |
| `promo_codes` / `promo_redemptions` | промокоды и однократность применения |

Внешние ключи включены на каждом соединении, индексы стоят на всех FK и
на `created_at DESC` для лент.

Скин не дублируется: один `skins.id` может входить в любое число кейсов
через `case_items`, а `UNIQUE (case_id, skin_id)` запрещает дубль внутри
одного кейса.

## Деньги

Все суммы — **целые числа в копейках** (`*_minor`). Ни одна денежная
величина не хранится и не считается во float. На баланс стоит
`CHECK (balance_minor >= 0)`, а списание выполняется условным `UPDATE`:

```sql
UPDATE users SET balance_minor = balance_minor - ?
 WHERE id = ? AND balance_minor >= ?
```

Если `changes = 0`, средств не хватило — проверка и запись это одна
операция, поэтому две параллельные попытки не могут обе пройти.

## Как работает открытие кейса

```
POST /api/cases/:slug/open        + заголовок Idempotency-Key
        │
        ├─ requireUser()                      сессия из httpOnly cookie
        ├─ rateLimit(user)                    60 открытий / 10 с
        │
        └─ transact(() => {                   BEGIN IMMEDIATE
             1. ключ идемпотентности уже есть → вернуть прошлый ответ
             2. прочитать кейс из БД          ← цена берётся здесь
             3. условное списание баланса     ← не хватило → 402
             4. загрузить дроп-таблицу, посчитать сумму весов
             5. crypto.randomInt(0, totalWeight) → предмет
             6. разыграть float, износ, StatTrak, цену экземпляра
             7. INSERT inventory_items
             8. INSERT case_openings (+ roll, total_weight)
             9. INSERT transactions
            10. сохранить ответ под ключом идемпотентности
           })                                 COMMIT / полный откат
        │
        └─ ответ клиенту → клиент запускает ленту к уже известному предмету
```

Тело запроса не содержит ничего, что влияет на исход: ни цены, ни
`skin_id`, ни шансов. Единственные входные данные — slug в пути и ключ
идемпотентности в заголовке.

## Система вероятностей

Вес — целое число «билетов». Вероятность предмета равна `вес / Σ весов`
по кейсу. Те же самые числа показываются на странице кейса до открытия.

Розыгрыш использует `crypto.randomInt(0, totalWeight)` — CSPRNG с
отбраковкой, без модульного смещения, которое даёт наивный
`Math.floor(Math.random() * n)`.

Каждое открытие сохраняет `roll` и `total_weight`, поэтому результат
можно перепроверить постфактум. Билет виден на экране выигрыша и в
истории открытий.

Экономика кейсов (`npm run test:probability`):

| Кейс | Цена | Средняя ценность | Маржа |
|---|---|---|---|
| Стартовый набор | 49 ₽ | 30 ₽ | 39% |
| Ночной рейд | 299 ₽ | 171 ₽ | 43% |
| Neon Division | 899 ₽ | 616 ₽ | 31% |
| Asiimov Protocol | 2 490 ₽ | 1 543 ₽ | 38% |
| Кузня клинков | 7 990 ₽ | 4 475 ₽ | 44% |
| Legacy Vault | 19 900 ₽ | 11 939 ₽ | 40% |

Закрытый партнёрский `Zevora Vault` бесплатный, поэтому маржи у него нет.

## Инвентарь

Предмет — это **экземпляр** скина, а не ссылка на каталог: при выпадении
разыгрываются float и износ, от них считается цена, StatTrak добавляет
25%. Поэтому два одинаковых скина в инвентаре стоят по-разному.

Множители износа: Factory New ×1.18, Minimal Wear ×1.06, Field-Tested
×0.92, Well-Worn ×0.81, Battle-Scarred ×0.72.

Список читается по `user_id` **из сессии** — параметра «чей инвентарь» в
API нет. Продажа и вывод сужены до `user_id = ? AND status = 'owned'`,
поэтому чужой предмет не найдётся, а повторная продажа своего вернёт 409.

## Безопасность

| Угроза | Защита |
|---|---|
| Подмена цены через DevTools | цена читается из БД внутри транзакции; в теле запроса поля цены нет |
| Подмена `skin_id` / результата | предмет выбирает сервер; клиент получает готовый ответ |
| Повторное открытие, двойной клик | `Idempotency-Key`, PK `(user_id, key)` — повтор возвращает прежний ответ |
| Двойное списание, гонки | `BEGIN IMMEDIATE` + условный `UPDATE` баланса |
| Отрицательный баланс | `CHECK (balance_minor >= 0)` |
| Чужой инвентарь | запросы сужены по `user_id` из сессии |
| Выдача без оплаты | предмет пишется только внутри той же транзакции, что и списание |
| Прямые запросы к API | `requireUser` / `requireOwner` на каждом мутирующем эндпоинте |
| SQL-инъекции | подготовленные выражения; в SQL подставляются только имена колонок из кода |
| Перебор пароля / флуд | лимиты частоты; одинаковый ответ на неверный ник и пароль |
| Утечка хеша пароля | ответы собираются в `presenters.ts` |
| CSRF | сессионная cookie `SameSite=Lax`, httpOnly |

### IMAGE

Берётся поле `image` записи датасета — это рендер Valve с
`community.akamai.steamstatic.com/economy/image/...`, ровно тот же
файл, который Steam показывает в инвентаре и на Торговой площадке.
Сопоставление идёт по `market_hash_name` с нормализацией (убираются
`★`, скобка износа, лишние пробелы), поэтому «AWP | Asiimov» получает
рендер именно Asiimov, а не общий AWP.

Это самое качественное изображение, которое источник отдаёт для
отдельного скина: `image` — единственное поле-картинка в записи, и это
не иконка-миниатюра, а полноразмерный рендер модели с прозрачным фоном.

Ни одна картинка не сгенерирована, не нарисована и не заменена
плейсхолдером. Процедурный SVG (`components/art/SkinArt.tsx`) остался
**только как обработчик `onError`**: если браузер не смог загрузить
рендер, вместо пустого прямоугольника рисуется силуэт. При рабочей сети
он не виден ни на одной странице.

### CACHE

По умолчанию в БД лежит **стабильный CDN-URL Valve**
(`image_source = 'steam-cdn'`) — Steam не разрешает произвольную
перераздачу своих файлов, поэтому изображения не скачиваются без явной
команды. Чтобы всё работало сразу после `npm install`, в репозитории
лежит снимок датасета `lib/server/skin-images.json` (63 записи) — сид
проставляет из него `image_url` и настоящую редкость Valve.

Локальный кэш включается явно:

```bash
npm run import:skins                 # только URL в базу (по умолчанию)
npm run import:skins -- --verify     # + HTTP-статус, content-type, размеры
npm run import:skins -- --download   # + скачать в public/skins/
npm run import:skins -- --force      # переимпортировать даже valid
```

С `--download` файл ложится в `public/skins/<slug>.png`, `image_url`
становится `/skins/<slug>.png`, `image_source` — `local`, а исходный
Steam-URL сохраняется второй строкой в `skin_images`. Папка
`public/skins/` в `.gitignore` — скачанные файлы Valve не коммитятся.

Импортёр идемпотентен: строки со статусом `valid` пропускаются (если нет
`--force`), `broken` перепроверяются всегда, не найденные в датасете
помечаются `missing`.

### TEST

```bash
npm run verify:images        # 20 эталонных скинов: URL и сеть
npm run verify:images -- --all
npm run verify:browser       # те же 20 в настоящем браузере
```

**Проверка URL.** Двухуровневая. *Структурная*: URL должен происходить
из записи датасета, у которой `weapon.name` и `pattern.name` встречаются
в имени скина — это и ловит подмену «иконка AK-47 вместо AK-47 |
Redline». *Сетевая*: HTTP-статус, `Content-Type: image/*`, размер в КБ и
ширина × высота из IHDR PNG. Плюс глобальная проверка уникальности.

```
структура:        20 верных, 0 расхождений
уникальность URL: у каждого скина своё изображение
сеть:             0 загрузилось, 20 не удалось (403 от egress-прокси)
```

Сетевая часть здесь не проходит не из-за URL, а из-за политики сети
песочницы: `*.steamstatic.com` заблокирован на прокси
(`connect_rejected … community.akamai.steamstatic.com:443`). На обычной
машине те же URL открываются, и `npm run verify:images` выполняет там
все сетевые проверки.

**Проверка в браузере.** `verify:browser` открывает настоящий Chromium,
проходит главную, все страницы кейсов, инвентарь и историю, прокручивает
их до конца (чтобы сработала ленивая загрузка) и считает по каждой
странице: сколько картинок скинов в DOM, сколько браузер декодировал и
сколько раз вместо рендера появился SVG-фолбэк.

```
страница                          скинов  декодировано  SVG-фолбэк
главная + последние выигрыши          19             9            0
кейс /starter-drop                    77            34            0
кейс /night-raid                      79            36            0
кейс /neon-division                   79            36            0
кейс /asiimov-protocol                86            43            0
кейс /blade-forge                     87            44            0
кейс /legacy-vault                    82            39            0
инвентарь                             41            41            0
история открытий                      41            41            0

эталонных скинов отрисовано:      20/20

```

Отдельно проверено открытие кейса: во время прокрутки ленты в кадре 79

изображениях та же страница показывает 36 фолбэков, при рабочих — 0.

Если хост изображений недоступен (песочница, CI), `verify:browser`
продолжает работу с подменой **байтов**: URL остаётся настоящим, из
приложения, а тело ответа отдаётся локально, чтобы `<img>` декодировался
и фолбэк не сработал. Режим печатается первой строкой. Механика
локального кэша отдельно проверена end-to-end на достижимом хосте: файлы
записались в `public/skins/`, строки в БД переключились на
`image_source = 'local'`, журнал `skin_images` записал
`200 image/png 1024×1024`, Next отдал файл как `200 image/png`.

### Связь с кейсами

```
case → case_items.skin_id → skins.image_url → рендер Valve
```

`image_url` читается одним и тем же полем на странице кейса, в ленте
открытия, в инвентаре, в истории дропов, в карточке предмета и в блоке
«Последние выигрыши» — отдельных источников картинок нет.

## Админка

`/admin` → вкладка **Кейсы**. Создание кейса занимает пару минут и не
требует правок кода:

```
Создать кейс → название, цена, описание
   → вкладка «Предметы» → Добавить скин → поиск → вес → Добавить
   → кейс сразу доступен на /cases
```

Редактор показывает сумму весов и пересчитывает шанс каждого предмета на
лету, а рядом — среднюю ценность и маржу, с предупреждением, если кейс
уходит в убыток.

Вкладка **Статистика** сравнивает «ожидание» (доля из таблицы весов) с
«фактом» (доля реальных выпадений) за сегодня / неделю / месяц / всё
время. Расхождение на малых выборках нормально и сокращается с ростом
числа открытий.

Вкладка **Редкости** позволяет завести свою редкость: цвет, эффект,
вес по умолчанию, порядок. Шкала — это строки в таблице, а не enum.

Кейс, который уже открывали, нельзя удалить безвозвратно (на него
ссылается история) — только архивировать.

## Партнёрская программа

Статус выдаётся **только владельцем** через `/admin → Partners`. В API
нет ни одного пути, позволяющего выдать партнёрку себе: и `PUT`, и
`PATCH`, и `DELETE` закрыты `requireOwner`. Уровни (`Partner`, `Creator`,
`Elite Partner`, `Zevora Ambassador`) назначаются вручную, автоматического
повышения нет.

Партнёр получает бейдж, персональный промокод (реально работающий на
странице «Бонусы»), партнёрскую ссылку и доступ к закрытым кейсам,
скрытым из общего каталога.

Реферальная атрибуция пока не реализована, поэтому в Partner Lounge
показывается **настоящая активность аккаунта** (открытия, оборот,
выигрыш), а не выдуманные переходы и регистрации.

## Тесты

```bash
npm run test:api          # 107 интеграционных проверок на чистом сервере
npm run test:probability  # χ² тест согласия, 1 000 000 розыгрышей на кейс
npm run test:simulate     # сквозной прогон по HTTP + сверка балансов
npm run verify:browser    # изображения скинов в настоящем браузере
```

**Что проверено**

*Открытие.* Списание ровно на цену кейса; выпавший предмет всегда из
таблицы кейса; предмет появляется в инвентаре; возвращается билет
розыгрыша.

*Двойной клик и повторы.* Повтор с тем же ключом возвращает то же
открытие и не списывает второй раз. 8 одновременных запросов с одним
ключом дают одно открытие и одно списание. Одинаковый ключ у разных
пользователей не конфликтует.

*Гонки.* При балансе на N открытий запускается N+25 параллельных
запросов: успешных не больше N, лишние получают 402, баланс не уходит в
минус, число предметов равно числу открытий.

*Подмена.* Поля `price_minor`, `skin_id`, `win`, `force` в теле
игнорируются — списывается цена из БД. В магазине списывается серверная
цена с наценкой, а не присланная.

*Доступ.* Открытие без сессии → 401. Админские эндпоинты обычному
пользователю → 403. Самоназначение партнёрки → 403. Продажа чужого
предмета → 409, предмет остаётся у владельца. Глобальная история закрыта
от игрока.

*Инъекции.* Пять вредоносных payload'ов в slug, мусорный `sort` и
`rarity`, кавычки в названии кейса, строка вместо массива id, дробный и
переполненный id, битый JSON — ничего не ломает выборку и не роняет
сервер.

*Вероятности.* χ² тест согласия при 1 000 000 розыгрышей на каждый из 7
кейсов (7 млн розыгрышей): все проходят при p = 0.001. Самый редкий
предмет — ★ Sport Gloves | Pandora's Box, p = 0.0284%.

*Сверка.* 1 200 открытий по HTTP: баланс сходится с суммой списаний до
копейки, число предметов равно числу открытий (1 200), стоимость
инвентаря равна сумме выпавшего (172 049,42 ₽ в обе стороны), история
содержит все записи, каждый выпавший предмет есть в таблице своего
кейса.

*Изображения.* 20 эталонных скинов отрисованы в браузере, 63 разных
скина с 63 разными URL, ни одной картинки, общей для двух скинов, ни
одного SVG-фолбэка.

*Интерфейс.* Полный прогон в браузере: вход, каталог, открытие с
анимацией, инвентарь, история, админка. Создание кейса через UI и его
открытие — 18 секунд. Отсутствие горизонтального скролла на 12 страницах
при ширине 390 px.
